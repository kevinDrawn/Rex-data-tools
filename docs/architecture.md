# 현재 코드 구조와 모듈화 방향

## 구현된 모듈

현재 패킷 해석과 CSV 저장을 실제로 분리했습니다.

```text
acquisition/
  rex_emg_uart_csv_logger.c  # 실행 흐름, Windows UART, 단축키, 시간 계산과 경로 생성
  csv_writer.h              # 저장 상태 자료형과 공개 함수
  csv_writer.c              # CSV 열 정의, 단위 변환, 버퍼와 파일 오류 처리
  frame_parser.h/.cpp        # 장치와 독립된 프레임 조립기
  live_session.h/.cpp        # GUI용 UART 작업 스레드, 저장과 표시 큐
protocol/
  rex_protocol.h            # 전송 규약, 채널 식별자, 공통 측정 자료형
  rex_protocol.c            # 페이로드를 측정값으로 복원
  rex_emg_wire.h            # 24비트 정수 복원
  rex_units.h               # 저장과 표시가 공유하는 단위 환산식
  test_emg_wire.c           # 정수 복원 경계값 테스트
tests/
  test_logger_modules.c     # 전체 채널과 CSV 결과 확인
```

## 데이터 흐름

```text
Windows UART → 프레임 수신 → rex_decode_payload() → RexBatch
                                                   ↓
                                      csv_writer_write_sample()
                                                   ↓
                                                 CSV 파일
```

`RexBatch`에는 단위 변환 전 EXO 6개 신호와 EMG 4개 채널이 들어 있습니다.
해석 모듈은 Windows와 CSV를 모르며, 저장 모듈은 UART 핸들이나 전송 바이트 순서를 모릅니다.
나중에 뷰어와 분석 코드는 같은 `RexBatch`를 받아 사용할 수 있습니다.

## 공개 함수와 상태

- `rex_decode_payload()`는 길이를 검사한 뒤 배치 자료형을 채웁니다. 실패하면 false를 반환합니다.
- `csv_writer_open()`은 지정 경로에 파일을 열고 헤더를 씁니다.
- `csv_writer_write_sample()`은 배치의 샘플 하나를 기존 단위와 CSV 열 순서로 변환합니다.
- `csv_writer_flush()`는 버퍼를 파일에 쓰고 스트림을 비웁니다.
- `csv_writer_close()`는 남은 데이터를 쓰고 파일을 닫습니다.

`CsvWriter`는 파일과 버퍼 상태를 소유합니다. 최초 사용 전에 0으로 초기화해야 합니다.
1 MiB 버퍼를 포함하므로 현재 로거처럼 정적 영역에 두거나 힙에 할당합니다.
각 함수의 반환값으로 오류를 확인합니다. 쓰기에 실패한 파일에는 더 쓰지 않으며,
현재 로거는 실패를 알리고 저장을 중지합니다. 다시 시작할 때 새로운 파일을 엽니다.

샘플 시간과 PC 시각은 실행부가 계산해 저장 함수에 전달합니다.
저장 모듈이 특정 운영체제 시계나 장치에 의존하지 않도록 하기 위한 구분입니다.

## 하드코딩 정리

하드코딩은 값이나 규칙을 코드에 고정하는 것이고, 모듈화는 역할별 코드를 나누는 것입니다.
파일을 나누는 것만으로 모든 고정값이 외부 설정으로 바뀌지는 않습니다.

| 분류 | 현재 위치와 처리 |
| --- | --- |
| 헤더, 채널 순서, 샘플·배치 크기 | 프로토콜 헤더와 해석 모듈에서 관리 |
| EXO와 EMG의 샘플 대응 비율 | 배치 크기에서 계산하고 정수 배수 관계를 컴파일 시 검사 |
| 각도·토크 변환 계수 | `rex_units.h`에서 저장과 표시가 공유; 펌웨어 단위 확인 필요 |
| COM 포트, baud rate | 기존 명령행 인수와 입력 방식을 유지 |
| 저장 경로, 단축키, PC 시각 | 실행부에 유지 |

프로토콜의 고정값은 필요합니다. 임의로 수정할 수 있게 하기보다 송신 코드와 일치하도록
근거와 버전을 관리해야 합니다.

## 향후 분리할 부분

GUI에서는 Windows 시리얼을 `live_session`으로, 프레임 조립을 `frame_parser`로 분리했습니다.
기존 콘솔 로거는 기존 수신 흐름을 유지합니다. GUI 수신기는 제한 시간이 있는 읽기를 사용합니다.
콘솔 수신 대기 중 단축키 지연과 프레임 유실 시 시간축 문제는 아직 남아 있습니다.

GUI는 전체 샘플 저장과 화면 갱신을 분리하고 최대 200배치의 큐를 사용합니다.
화면은 최근 60초만 유지하며 전체 샘플은 별도 CSV에 기록합니다.
GUI 코드와 사용법은 [뷰어 설명](../viewer/README.md)을 참고하세요.
